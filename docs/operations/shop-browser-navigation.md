# 확장 0.6.0 브라우저 수집

- 비활성 수집 탭 하나를 재사용한다. 통합검색 `https://m.search.naver.com/search.naver?where=m&query=키워드` 로드 → 상단 쇼핑 메뉴 실제 클릭 → 쇼핑 결과 로드 → 한 화면 스크롤 → 750ms 대기 → 순위 읽기 순서다. 메뉴를 못 찾으면 오류로 멈춘다.
- 서버 자동 전환은 제거했다. watchdog 명령·스케줄이 없고, PR #30의 과거 캐시 플래그도 전환을 활성화하지 못한다. 과거 서버 전용 큐 작업은 종료한다. 브라우저/search 분석은 서버 배치로 수집하지 않는다. 별도로 선택한 기존 API 방식은 유지한다.
- 차단 탭을 닫지 않는다. PR #29의 기존 탭 검사로 사람이 보안문자를 해결하면 이어간다. 통합검색에서 차단돼도 해결 뒤 쇼핑 메뉴를 클릭한다. 미해결 시 3분 뒤 재확인한다. 간격은 기존 정책(2초 이상, 차단마다 +0.3초, 최대 10초)을 유지한다. 자동 보안문자 풀이와 IP 변경은 없다.
- 노출 재확인 로직과 deploy.sh는 수정하지 않는다. 배포·마이그레이션·운영 작업 없음.

검증: `node --test tests/extension/*.test.cjs`, `node tests/extension/shop-navigation.browser.cjs`, 관련 PHP 테스트. 브라우저 검증은 네트워크를 모의 응답으로 대체하며 실제 네이버 정상 상품 수집은 별도 수동 확인이 필요하다.
